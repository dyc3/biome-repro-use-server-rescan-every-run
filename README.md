# The daemon rescans the whole project on every `biome check --use-server` run, and its memory grows each time

When a configuration enables a rule that needs the project scan, such as `noImportCycles`, every `biome check --use-server` run makes the Biome daemon scan and index the whole project again, even though nothing changed since the previous run. Each scan also allocates new copies of every indexed file's syntax tree and module information, and the old copies are never released, so the daemon's memory grows on every run.

## Reproduce

Requires Linux or macOS, Python 3 and Biome. `src/` is generated by `gen.py` (400 TypeScript modules that import each other, about 4.8 MB) and is already included. `biome.json` enables `noImportCycles`, which makes Biome scan the whole project.

```shell
BIOME=/path/to/biome ./repro.sh 6
```

`BIOME` defaults to `biome` on the `PATH`. The script starts its own daemon with a private cache directory, so it doesn't interact with a daemon started by an editor. It runs `biome check --use-server --verbose .` repeatedly and prints the scan time and the daemon's resident memory after each run.

## Expected

Runs after the first reuse the daemon's index of the unchanged project: the scan takes much less time than the first one, and the daemon's memory stays about the same.

## Actual

Every run takes as long to scan as the first, and memory grows by about 115 MB per run (Biome built from the commits merged in biomejs/biome#12441, Linux):

```
in-process:
  Scanned project folder in 32ms.
  Checked 401 files in 132ms. No fixes applied.
daemon (pid 709), RSS before the first run: 44 MB
  run 1: Scanned project folder in 31ms. Checked 401 files in 383ms. No fixes applied. daemon RSS: 249 MB
  run 2: Scanned project folder in 30ms. Checked 401 files in 379ms. No fixes applied. daemon RSS: 367 MB
  run 3: Scanned project folder in 30ms. Checked 401 files in 382ms. No fixes applied. daemon RSS: 485 MB
  run 4: Scanned project folder in 30ms. Checked 401 files in 392ms. No fixes applied. daemon RSS: 590 MB
  run 5: Scanned project folder in 30ms. Checked 401 files in 387ms. No fixes applied. daemon RSS: 704 MB
  run 6: Scanned project folder in 30ms. Checked 401 files in 383ms. No fixes applied. daemon RSS: 821 MB
```

On a 9,500-file project the scan takes about 360 ms of a 2.5 s run.

## Cause

The CLI doesn't ask the daemon to watch the project (`watch` is only set in watch mode, `crates/biome_cli/src/runner/mod.rs`), and the scanner only skips a project it is already watching (`crates/biome_service/src/scanner.rs`, `index_project`). So every run scans everything. The scan runs in a scanner epoch, which publishes each file by creating new `ParsedSource` and `ModuleInfo` Salsa inputs instead of updating the existing ones. Salsa inputs can't be deleted, so the previous copies stay in memory.
